# Шаг 15. Распространить механизм на остальные поля

## Цель

После подтверждения сценария на баннерах переиспользовать общий helper, job и сервис для других изображений проекта без создания отдельных job-классов.

## Зависимости

- Баннерный сценарий полностью проверен на шагах 11-14.
- Есть уверенность, что очередь стабильно обрабатывает `images`.

## Кандидаты на подключение

- `app/Filament/Resources/Products/Schemas/ProductForm.php` для `og_image`.
- `app/Filament/Resources/Categories/Schemas/CategoryForm.php` для `og_image`.
- `app/Filament/Resources/PageSeos/Schemas/PageSeoForm.php` для `og_image`.
- `app/Filament/Resources/Shipments/Schemas/ShipmentForm.php` для `images.file_path`.
- XML-импорт товаров для `ProductImage.file_path`.

## Задачи для Filament-полей

1. Для каждого поля определить:
   - модель;
   - атрибут;
   - disk;
   - directory.
2. Заменить настройку `FileUpload` на `ImageUpload::webpConvertibleUpload()`.
3. Добавить observer или расширить существующий observer модели.
4. Dispatch'ить `ConvertModelImageToWebpJob` с нужной моделью, ключом, атрибутом, disk и source path.
5. Проверить, что soft delete не удаляет файл, если модель поддерживает soft deletes.
6. При force delete удалить текущий файл модели.
7. Добавить focused тесты на dispatch и безопасное обновление.

## Задачи для XML-импорта

1. Не привязывать импорт к Filament.
2. После сохранения исходника и записи `ProductImage.file_path` выбрать один из вариантов:
   - dispatch `ConvertModelImageToWebpJob` для `ProductImage.file_path`;
   - или конвертировать синхронно внутри import job, так как импорт уже выполняется в фоне.
3. Не создавать отдельную job, если достаточно универсальной `ConvertModelImageToWebpJob`.
4. Убедиться, что ошибки конвертации не роняют импорт товара.

## Важные правила

- Не распространять механизм до ручного подтверждения баннеров.
- Не мигрировать старые `.jpg`/`.png` записи автоматически в рамках этого шага.
- Если нужен backfill, оформить отдельную artisan-команду отдельным планом.
- Для PNG с важной прозрачностью можно позже добавить per-field политику или lossless WebP.

## Проверка

Для каждого подключенного поля:

1. Загрузить `.jpg`.
2. Убедиться, что запись сначала сохраняет исходник.
3. Дождаться очереди.
4. Убедиться, что поле заменилось на `.webp`.
5. Проверить API/страницу, где это изображение используется.
6. Проверить, что `.webp` не ставится на повторную конвертацию.

## Готово, когда

- Механизм переиспользуется без дублирования job-классов.
- Новые поля проходят тот же сценарий, что и баннеры.
- Для каждого поля есть минимальная проверка observer/job/API или UI.
