# Шаг 08. Расширить ValidImageUpload списком расширений

## Цель

Сделать правило валидации переиспользуемым: старые поля продолжают принимать прежний набор изображений, а WebP-конвертируемые поля принимают только `jpg`, `jpeg`, `png`, `webp`.

## Зависимости

- Существующее правило `ValidImageUpload`.

## Файлы

- Изменить: `app/Rules/ValidImageUpload.php`.
- При необходимости обновить тесты правила, если они уже есть.

## Задачи

1. Найти текущий список разрешенных расширений в `ValidImageUpload`.
2. Добавить конструктор с параметром списка расширений:

```php
public function __construct(
    private readonly array $allowedExtensions = ['jpg', 'jpeg', 'png', 'gif', 'bmp', 'webp'],
) {}
```

3. Внутри проверки использовать `$this->allowedExtensions`.
4. Нормализовать список расширений к lower-case, если в проекте возможна передача значений с разным регистром.
5. Сохранить существующее поведение по умолчанию:
   - `jpg`;
   - `jpeg`;
   - `png`;
   - `gif`;
   - `bmp`;
   - `webp`.
6. Убедиться, что фактическая проверка картинки через `getimagesizefromstring()` остается на месте.
7. Не менять сообщения валидации без необходимости.

## Важные правила

- Расширение файла проверяется в lower-case.
- `JPEG` и другие варианты регистра должны обрабатываться корректно.
- Старые формы не должны внезапно перестать принимать GIF/BMP.

## Проверка

- Старый вызов `new ValidImageUpload()` работает как раньше.
- Новый вызов `new ValidImageUpload(['jpg', 'jpeg', 'png', 'webp'])` запрещает GIF/BMP.
- Невалидные bytes по-прежнему не проходят проверку.

## Готово, когда

- Правило принимает список разрешенных расширений.
- Значение по умолчанию сохраняет обратную совместимость.
- WebP helper из следующего шага может использовать узкий список расширений.
